# 汐序 · Xixu Planner

**让课表、DDL、备忘录和生活资料，成为一位有出处、会追问的个人秘书。**

汐序是一款面向 HarmonyOS 的本地优先规划与知识整理应用。它把课程、作业截止、会议、展示和碎片记录放在同一个工作空间：简单安排先在本机处理，资料检索保留来源；复杂问题再按需连接个人电脑或模型。助手提出修改后，先给你核对，再写入日程。

> **当前阶段：早期内测 / 开发源码。** `main` 已加入综合助手、流式请求、完整备份和时间信箱代码，并补充了分块原件、ZIP64、历史快照、通知核对依据、可选本地 CrossEncoder 与独立联网搜索工具；新增路径尚未完成运行、原生编译及真实设备验收。历史标签 [`v0.8.11-source.1`](https://github.com/jiajunlin949-stack/xixu-planner/tree/v0.8.11-source.1) 保留当时的源码快照；旧 CI 结果不代表当前新增功能已通过。GitHub 源码更新也不会自动更新手机安装包。

## 为什么做汐序

课表能告诉你何时上课，却未必包含导师在群里补充的提交要求；日历能保存一个 DDL，却不一定能找回后来修改日期的通知。备忘录里还有大量尚未整理成任务的小事。

汐序围绕这些日常问题组织能力：**先把资料留好，再找出相关线索，最后由用户决定是否行动。** 产品主线是个人规划和有来源的知识检索；时间信箱则把重要事项、自己的承诺和到期后的真实反馈连起来。

## 核心流程

下面的对话是功能设计示例，不是已运行的演示记录。

### 1. 一件事情可以分几句话说

```text
你：下周交作业。
汐序：具体周几？
你：周三晚上八点。
汐序：保留原事项，补全日期与时刻 → 展示预览 → 等你确认。
```

- 多会话与独立草稿；待补信息按会话隔离，避免把另一段对话的日期接过来。
- 本机规则处理明确的记录、待办和部分调课指令；不必每次都调用模型。
- 查询按实际课表、调入/调出课程、事项和学习时段核对占用；截止风险单独列出。
- 工具参数先校验，已有事项修改还要核对来源 ID 和版本。

### 2. 从资料里发现漏记的事

```text
手动导入聊天 / 文档，或保存碎片记录
→ 规则提取行动与截止线索
→ 保留原文、来源时间和版本
→ 与已有事项比对
→ 展示待核对建议
→ 你确认归自己处理，再核对并加入日程
```

例如一条“11月5号前提交开题报告”的通知，可以成为待核对事项。群体通知不会自动认定为你的任务；未知的原始时间不会用导入时间代替。已有的建议会在源内容变化后重新核对。

### 3. 问“这件事后来改了吗”

时序来源规则提取通知中的日期、地点或范围变化，保留新旧说法及出处。单条通知明确写出“原定日期 → 改后日期”时，可以并列展示；跨通知无法确认同一事项、班级或考试批次时，可选择当前采用的通知并明确适用范围，保存全部出处和来源版本；相同版本组再次提问可沿用核对结果，来源变化后重新核对。

这不是“发布时间更晚就自动覆盖”的策略，也不会在回答过程中直接更改日程。

### 4. 数据发送和日程修改都可核对

- **数据发送前**：手机发往电脑、电脑片段发往云模型，分别展示核对界面。问题、历史消息和来源片段可以编辑或排除；提供电话、邮箱、带标签编号、姓名/证件/Key模式和本机持久隐藏词表。
- **操作保存前**：展示事项、笔记或调课的前后变化。每个独立建议分别接受；同一次调课作为一组保存。
- **操作保存后**：变更日志保留前后记录。撤回时核对当前内容，避免覆盖后续编辑；支持逐组撤回，并可从每日首次使用或手动保存的完整业务快照按日期恢复。
- **模型回复中**：提供流式文字、停止和超时处理；未完整结束的结构化动作不会执行。

### 5. 时间信箱：给之后的自己留一句话

用户主动启用并选择重要事项后，可收到基于真实记录、以未来视角写来的信：

```text
重要事项临近 → 拆信 → 封存一句回信 → 到期对账 → 留下允许下次引用的真话
```

信箱默认关闭，每周最多两封、每个事项最多三封；支持温柔、实话和直接三种语气。来信只引用已记录的事项、时间、标记状态和用户同意复用的原话，不编造熬夜、地点、睡眠或实际进度。回信不会自动生成任务。

## 规划、记录与导入

- 今天视图、日历、每周课表、个人待办与到期事项。
- 自然语言速记、课程调整、备忘录、碎片记录和上次编辑时间。
- 液态玻璃导航与主题色界面；信封、变更对照和会话沿用同一配色，支持减少动态效果。
- 完整手机 ZIP 备份/恢复源码：快照包含课程、事项、笔记、碎片、对话、信箱与变更记录，并打包仍被引用的独立图片和原始文档；以 SHA-256、CRC 和清单核对后再确认替换。连接密钥不进入资料备份。

| 导入入口 | 代码支持的格式 | 范围 |
| --- | --- | --- |
| 课表 | Excel、PDF、原生 OCR 路径 | 识别后核对课程与节次；原生能力需要手机环境。 |
| 备忘录 / 文档 | TXT、Markdown、CSV、HTML、约定格式 JSON、DOCX、PDF、PNG / JPEG / WebP；hdoc / 旧 DOC 可归档原件 | 分块保留文件与校验值；扫描 PDF 在手机尝试本机 OCR；仅原件状态明确显示，提取视图不能代替原件。 |
| 电脑聊天资料 | QQ 标准 TXT；QQ、钉钉、微信的约定 JSON / CSV | 手动选文件、预览后确认，保留发言者、会话、原始发送时间和消息标识。不是账号自动采集。 |

不同客户端可导出的内容与格式并不相同，实际样本仍需核对。文件内的媒体引用不等于已取得媒体字节；不自动下载未知附件。华为 `.hdoc` 现可完整归档与原样导出，正文和内嵌图片尚待可靠解码。

## 两种个人使用方式

| | 手机独立模式 | 可选电脑扩展模式 |
| --- | --- | --- |
| 用途 | 日常记录、导入、课表和本机检索 | 在手机资料之外检索手动导入的聊天与工作资料 |
| 电脑要求 | 电脑关机也可使用本机记录与检索 | 访问电脑资料时需要配套服务在线 |
| 检索 | 关键词、BM25 风格评分、词汇特征哈希与上下文预算 | SQLite FTS5；可选本地 Embedding、Milvus / Chroma、RRF 与轻量精排 |
| 数据保存 | App 本地快照与原件；网页预览使用浏览器存储 | SQLite 权威正文与版本，加独立原件文件 |
| 模型 | 可选配置；明确的本机指令不依赖模型 | 可选电脑模型；资料发往云端前再次核对 |

**手机没有内嵌 Python Chroma，也不依赖 Docker 才能记录和检索。** Chroma / Milvus 是可选电脑侧索引，不能替代原始资料备份。笔记与原件同步需要用户主动确认，默认不传播删除。

```mermaid
flowchart LR
    U["手动记录 / 导入"] --> A["HarmonyOS App<br/>ArkTS + ArkWeb + JavaScript"]

    T --> S
    L -->|"可选：核对后查询"| P["个人电脑 FastAPI"]
    P --> D["SQLite / FTS5<br/>权威原文与来源版本"]

    L -->|"发送前核对"| M["用户配置的云模型"]

```

| 层次 | 技术与职责 |
| --- | --- |
| HarmonyOS 外壳 | ArkTS、ArkUI、ArkWeb；文件选择、HTTP / SSE、OCR、提醒和安全存储桥接。 |
| 应用界面 | HTML / CSS / 原生 JavaScript 模块（在 ArkWeb 内运行）；Hyalite、Lucide、Nunito；按动画帧合并流式文字更新。 |
| 秘书编排 | 本地意图规则、会话槽位、共享 JSON Schema Tool Registry、参数与版本校验、用户确认执行。 |

## 快速开始

以下是读者可自行执行的操作说明，不代表当前开发版本已经完成运行验证。

### 网页预览

在仓库根目录使用 Node.js 22：

```powershell
git clone https://github.com/jiajunlin949-stack/xixu-planner.git
cd xixu-planner
node work/prepare-native.cjs
node work/serve-native-preview.cjs
```

打开 `http://127.0.0.1:8767/`。预览服务只监听本机，资料保存在当前浏览器；不需要模型 Key、电脑知识库或 Docker。网页预览没有 HarmonyOS 原生桥接，不能代替真实 OCR、提醒、安全存储或手机模型连接验收。

### 可选电脑服务

使用 Python 3.12：

```powershell
cd companion
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m xixu_hub serve --open
```

默认管理页位于 `127.0.0.1:8765`。需要手机配对时使用 `serve --lan --open`，再通过管理页生成短期连接信息；手机 HTTPS 端口为 `8766`。默认文字检索不需要 Docker 或语义模型。

向量依赖、Chroma / Milvus 选择、手动聊天导入及配对说明见 [配套服务指南](companion/README.md)。扩展服务的启动、账号配置与个人资料均由使用者自己管理，不随源码提供。

### HarmonyOS 原生开发

在 DevEco Studio 中打开 `xixu-harmony/`，安装构建配置所需 SDK，并使用自己的应用身份、设备配置和签名材料。工程配置当前为 target SDK 26、兼容配置 API 12；**该兼容配置不构成新增原生能力的低版本适配结论**。

Windows 构建脚本支持指定安装位置：

```powershell
$env:XIXU_DEVECO_HOME = 'C:/Program Files/Huawei/DevEco Studio'
node xixu-harmony/build-release.cjs
```

生成、签名、安装到设备和发布内测是独立步骤。公开仓库不提供原应用的签名材料，也不会自动上架。

## 本轮改进与使用条件

本轮针对原先的限制修改了实现，详细对照见 [导入、备份与检索优化](companion/LIMITS_UPGRADE.md)。

- **hdoc 可保留原件**：支持完整归档、哈希核对和原样导出，明确显示“仅原件”；正文解码及真实74条全量迁移仍未完成。
- **PDF 与大文件**：扫描页尝试本机 OCR，未识别页保留图像与原件。取消原件20MiB、文档每批25MiB及PDF固定50页门槛；超出展开预算时按原件归档，不能据此宣称所有格式都已识别。
- **备份与历史**：新增流式 ZIP64、浏览器文件/OPFS保存，去掉固定2GiB/网页64MiB门槛；同时纳入历史快照与其原件。容量仍取决于存储、浏览器与元数据预算；只能恢复实际记录过的日期时刻，完整恢复尚未运行验收。
- **通知与隐私**：批次核对依据绑定来源版本；两端可维护姓名等隐藏词表。未知通知权威性、未知姓名及图片敏感内容仍需用户判断，发送确认保留。
- **检索与联网**：可配置本地 CrossEncoder，缺模型时明确回退；电脑扩展提供独立 Brave Search 工具，需搜索服务 Key，核对后只发送公开搜索词并返回摘要来源。配置能力不等于已有真实语料成绩或服务验证。

资料入口保持手动选择与确认；不自动登录、解密账号库、监听文件夹或采集全部附件。这是产品范围。所有本轮新路径仍为未运行验收的源码。

其他实现与历史状态见 [综合助手说明](companion/ASSISTANT_UPGRADE.md)、[项目状态](docs/PROJECT_STATUS_AND_PLAN.md)、[版本记录](CHANGELOG.md)。
