# Agent 架构与设计

汐序将用户消息、资料变化和已启用的时间信箱接入同一条任务链：

```text
来源 → 身份与内容版本 → 独立任务 → 执行批次
    → 本机规则 / 检索 / 经核对的模型请求
    → 持久结果 → 原会话交付 → 差异预览 → 确认保存
```

## 领域模型

| 概念 | 职责 |
| --- | --- |
| Trigger | 记录来源和内容版本，重复资料用内容游标去重 |
| Thread | 保存会话或资料的关联关系 |
| Ticket | 保存任务归属、授权、输入引用和处理状态 |
| Assignment | 标识一次执行批次，区分取消、重试和迟到结果 |
| Outbox | 在展示前保存报告，通过固定消息 ID 完成交付 |

每段对话拥有独立草稿与请求。操作卡绑定原助手消息；重试旧问题采用原问题之前的历史。来源资料作为证据进入上下文，工具建议通过参数校验和用户确认后保存。

## 代码职责

| 模块 | 职责 |
| --- | --- |
| `assistant-engine.js` | 准入、授权、状态转换、执行批次、结果回执 |
| `assistant-runtime.js` | 执行队列、前台监督、取消、来源更新和上下文 |
| `assistant-results.js` | 消息绑定、编辑草稿、持久结果交付与恢复 |
| `assistant-workbench.js` | 分页、筛选和任务操作 |
| `assistant-network.js` | 发送核对、模型协议、SSE、有界工具循环 |
| `assistant-core.js` | JSON Schema 工具、多轮槽位、日程 Diff 和撤回 |
| `assistant-intelligence.js` | 承诺线索、时序证据和时间信箱 |
| `shared/` | 手机与电脑共用的工具和供应商目录 |

模块通过 `manifest.json` 组合为离线应用资源。业务模块维护职责，原生桥接负责文件、网络、密钥和系统提醒；生成文件统一换行与序列化，便于复现和审查。

## 调度与恢复

- 前台用户请求优先，资料更新在去重队列中合并处理；普通笔记仅在具有行动线索或既有追踪关系时建立资料任务。
- 请求等待发送核对时让出执行槽；实际网络连接通过独立租约控制。
- 报告保存后交付，重复回执保持幂等。重新打开应用时读取任务档案与待交付结果，外部中断请求提供继续入口。
- 已取消、被新资料取代或原消息发生变化的执行批次在交付前再次核对。
- 队列维护、每日快照与界面时间更新共用前台时钟。

## 数据与执行边界

业务快照与独立原件是权威资料，检索索引可重建。来源保存原始时间、导入时间、版本和片段位置。较早对话通过有界摘录和显式回查工具进入上下文；新增证据再次进入发送核对。

日程修改采用“读取当前版本 → 构建前后差异 → 勾选接受 → 保存业务与回执”的流程。变更记录保存前后数据，撤回时核对当前版本；任务恢复与日程写入分别处理。

电脑端使用 SQLite 事务保护批次导入、快照提交和一次性配对。一次配对的读取、尝试计数、设备创建与配对码消费位于同一写事务中。
