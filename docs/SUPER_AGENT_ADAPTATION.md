## 当前产品的质量目标

以手机优先、用户手动导入资料的现实使用方式为准：先把记录、接话、查询、核对写入和恢复做好，再按实际需求扩展后台部署。评判依据是用户能否顺利完成事情、数据能否追溯、手机是否顺畅，以及代码是否容易维护；不以组件数量或与官方原型相似程度评判。

2026-11-01 的进一步源码收尾：

- 重试旧消息只使用其之前的对话，避免把原回复和后来的消息混入原请求上下文。
- 同一份资料出现新版时，旧版未结束的自动整理任务标记为被新版取代，保留过程记录；旧执行批次不能再提交结果。来源正文不会删除。
- 已处理的交付回执、无在途任务的恢复和已停用来源不会重复写入；历史事件整理同时考虑来源条目容量。
- 取消旧请求仅移除对应请求对象；原消息修改时间变化后，旧待交付结果不会挂到修改后的问题下面。
- 工作台保留查看模式，任务界面刷新按动画帧合并；这些是源码调整，尚无手机性能测量结果。

本轮继续处理前三项日常使用问题：

- 保存函数明确返回成功/失败，一条保存路径只序列化一次业务快照。助手状态、队列、历史消息等内部保存跳过事项完成记录扫描、来源扫描与系统提醒同步；真实日程变更仍同步提醒。保留原有单份原子快照格式，没有引入第二套存储或迁移用户数据。
- 操作卡、快捷回复和保存后的入口放在对应助手消息下面，点击时按消息 ID 和任务 ID 重新绑定；旧结果不会作为新请求的浮动操作恢复。原问题被编辑、建议失效或任务结束时不再提供对应写入按钮。
- 保存日程后的任务回执保留在该任务结果中；更新原助手消息时不改动另一段对话。后台刷新时暂存卡片中正在编辑的字段，来源建议变化后使暂存值失效。
- 工作台增加每页 20 项的分页、总数和前后翻页；保留当前筛选与页码，列表缩短时校正到有效页面。没有删除较早任务。

## 模块职责

- `assistant-engine.js`：领域状态、授权、执行批次、交付回执和确认准备。
- `assistant-runtime.js`：队列、上下文、来源接入、取消和前台监督。
- `assistant-results.js`：消息绑定、编辑草稿、结果交付与恢复。
- `assistant-workbench.js`：分页、工作台和用户命令。
- `assistant-network.js`：发送核对、协议、流式响应和有界工具循环。

旧全局忙碌状态别名与无调用包装器已剪除；只读工具结果不再重复获取。具体审查记录见 [代码清理](CODE_CLEANUP.md)。

## 实现链路

```text
用户消息 / 手动导入后的本机资料 / 已启用的时间信箱
  → Source Adapter：来源与内容版本
  → Trigger：去重的输入事件
  → Thread：来源内的上下文归属
  → 内置规则准入 + Mandate：本机读取、提出建议、申请发送核对
  → Ticket：独立于网络连接的持久任务
  → Assignment：本次尝试、阶段、进展时间
  → 规则 → 本机检索 → 按需电脑 → 按需模型/只读工具
  → Report + Outbox：先保存结果，再交付到原对话
  → 需要人处理时进入工作台；写入仍走现有差异核对
```

## 已写入的功能

| 能力 | 具体行为 | 主要源码 |
| --- | --- | --- |
| 独立领域引擎 | 单一状态写入入口，事务式保存失败回退；任务与一次执行分离 | `assistant-engine.js` |
| 来源准入与去重 | 对话、已导入资料、时钟使用不同来源身份；资料哈希游标不随短期事件归档丢失 | `assistant-engine.js`、`assistant-runtime.js` |
| 任务授权 | 导入资料仅提供证据和建议；只有用户消息可以申请模型核对，不自动授予日程写入权限 | 同上 |
| 多对话调度 | 对话分别绑定请求；通常并行一至两项，前台用户任务优先；有前台补位，模型连接仍受共享上限约束 | `assistant-runtime.js`、`assistant-network.js` |
| 发送核对队列 | 一次只展示一个核对界面；后台对话等待回到该对话；等待用户时让出执行槽 | `assistant-network.js` |
| 分步只读工具 | 模型可按需查笔记、查实际日程、回查当前对话原文；一轮最多三次模型请求，新增证据发送前再次核对 | `assistant-network.js`、`assistant-core.js` |
| Inline / Spill | 近期消息与相关旧摘录共享 2600 字符内容预算，原文保留在本机；`recall_conversation` 可回查当前任务历史 | `rag.js`、`assistant-runtime.js` |
| 上下文关联 | 工作台显式关联其他本机来源；关联只增加证据，不扩大授权；来源更新会使进行中的建议要求重新核对 | `assistant-engine.js`、`assistant-runtime.js` |
| 持久交付 | 报告与待交付结果先一起保存；本机交付使用固定消息 ID，重新交付不调用模型 | `assistant-results.js` |
| 恢复与停止 | 重启后在途任务标记中断；用户选择继续才重新处理，云端仍重新核对；取消只影响对应任务 | 同上 |
| 监督与注意力 | 前台检查超时/停滞；待发送、待补充、待确认、失败与中断进入工作台；正常处理不逐步弹通知 | 同上 |
| 现有能力整合 | 资料哨兵和时间信箱纳入任务来源；日程确认同时结束对应任务；备份保留任务档案 | `assistant-intelligence.js`、`assistant-core.js`、`full-backup.js` |

## 上下文、结果与数据边界

- 对话提交以消息 ID 和 SHA-256 内容版本入档；任务继续前核对原消息是否仍然一致。
- 任务输入保存来源引用与内容指纹；结果包含回答、建议及有限来源摘录。运行记录不保存模型密钥。
- 一般会话的较早摘录先在最近 200 条旧消息中筛选，最多三段；显式回查工具可检索本次任务保留的整段对话快照，不能任意读取未关联的其他对话。
- 关联来源只作为证据进入预览；资料中的命令不能变成用户指令。新增证据再次核对后才发给模型。
- 时间戳按原请求保存；跨日恢复含相对日期的请求时要求明确具体年月日，不静默按恢复当天重新解释。
- 日程写入仍保留参数校验、来源版本检查、差异预览与确认。任务恢复不会回放日程写入。
- 近期任务、事件和交付档案有明确容量上限；仅整理已结束且已交付的记录，不为了接新任务静默丢掉未处理任务。用户原笔记与完整对话不随任务档案整理删除。
- 一份任务可以先后有多个执行批次。跨来源引用只是上下文关系；同一个人不同服务的身份没有被自动合并。

## 与官方原型的对应及实际范围

这是一套适合汐序的应用内实现，不能等同于把 DeepSeek 官方原型的所有部署能力移植到手机。

- Source 使用汐序已有的对话、手动导入资料与本机时钟；不是 GitHub/飞书账号监听器。
- 规则准入直接识别来源权限并排队，不额外用模型审批每条本机资料，也没有运行官方的独立评估 Session。
- Executor 是隔离的请求对象与异步执行槽，不是多个独立模型进程、操作系统沙箱或可运行任意 shell 的 Worker。
- 手机任务运行依赖应用存活。前台监督不是独立守护进程；杀进程、关机、操作系统冻结后不保证继续运行。重新打开后恢复任务档案。
- 自动恢复的是尚未交付的本机结果和已入档但未开始的工作；进行中的外部请求需人工选择继续，不保证外部服务“恰好一次”。
- 云端常驻、外部账号订阅、部署凭据和系统后台服务没有被假装成已接通功能。现有配对电脑和模型配置仍需用户提供。
