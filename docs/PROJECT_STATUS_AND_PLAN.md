## 产品定位

面向学生与个人日常安排的 AI 辅助规划器：把课程、会议、作业截止、展示、备忘录和零碎记录关联起来，提供来源可核对的问答、时间冲突检查，以及确认后执行的记事、规划和调课。

AI 应用不取决于是否把聊天界面命名为 Agent。模型理解、基于资料生成回答和工具执行可以与确定性规则共同工作；本地规则能可靠解决的问题不必调用模型。没有模型密钥时的本地规则回复，不应称为大模型推理。

## 当前三部分不能混为一谈

1. **手机 App**：ArkTS 原生外壳与原生桥接，HTML/CSS/原生 JavaScript 实现主要界面，不是 React。模块经 `work/prepare-native.cjs` 生成离线资源；生成的 `rawfile/app.js` 不是单个手写源码文件。
2. **电脑知识库**：原私人知识库仍是独立工程，未将其数据库/配置/完整历史公开。当前新增 `companion/` 为整理后的可选个人服务源码，提供SQLite权威正文、Milvus/Chroma适配、手动文件导入和手机备忘录主动同步；其运行验收边界另列。
3. **公开仓库**：隐私清理后的独立副本，不包含原私有 Git 历史、用户资料或签名材料。它不与开发目录自动同步。

## 已发现的三项具体代码缺口

- `web/modules/agent.js`：除调课外，普通简单动作可能在本地规则执行前先经过电脑问答或手机模型，增加成本。电脑只读问答返回 `action:none` 时，可能吞掉本应创建日程或笔记的意图。
- `web/modules/productivity.js`：原 `busyIntervals` 未使用实际日期的调课结果，并漏算有时间的会议/考试。
- `web/modules/knowledge.js` 与原生桥接：现有 `pair/health/search/chat/excerpt` 是查询接口，不是手机资料上传/更新/删除同步接口。

本轮已对前两项做限定修复与回归：新增本地路由41项、规划占用30项专项通过；普通问句不误建日程、确认前无写入、确认可撤销均有断言。普通新任务的本周/下周选择会保留原事项和时刻，不再复用调课的节次追问。不把第三项或下述路线图标为已实现。完整测试结果以本次 CI 报告及提交记录为准。

会议/考试当前无可靠结束时刻，自动规划暂按与普通任务一致的一小时估算并显示提示；跨午夜只裁剪本日，不虚构次日安排。因此不能把这次修复称为任意真实时长/跨日事件完整支持。未提供开始时间的会议/考试会先询问；作业23:59默认值明示需要核对。

普通记事/任务尚无覆盖任意表达的通用多轮补全状态机：本周/下周快捷选择已闭环，但缺日期或缺时刻时，不保证单独回复“18点”就能续接，当前可重述完整安排。不能把有限规则覆盖称为完整自然语言理解。

## 目标架构：兼容多，但入口保持简单

```text
手机课程/任务/备忘录/碎片 + 经授权的外部资料
  → 原件归档 + 规范化记录 + 来源/时间/版本
  → SQLite权威记录与全文索引
  → Embedding → VectorStore适配器（先Milvus，再Chroma）
  → 结构化日程查询 + 混合检索 + 来源核对
  → 本地规则 / 模型网关 / 可选联网工具
  → 预览 → 确认 → 执行 → 撤销或回执
```

向量库是可重建的检索索引，不是课表、时间、原件和业务事务的唯一事实源。替换向量库不应重写秘书或UI，也不要求用户同时部署多个数据库。

### 数据与同步接口

- 稳定记录ID、设备/所有者、资料类型、原始创建/编辑时间、独立入库时间、内容版本、来源与原件哈希。
- 设备仅获自身资料 `upsert/delete/status` 等窄权限；不能为省事发放电脑管理员凭据。
- 增量游标、幂等批次、删除标记、断线重试、版本冲突保全；不能仅传每次问答选中的片段冒充全量同步。
- 向量适配接口覆盖 `upsert/search/delete/reindex/health`，契约测试包含删除/更新后不返回旧正文、维数不匹配与服务中断。
- 原件、文字投影、OCR/ASR结果分开保存；全文、图片和时间缺失都必须报告，不能静默裁剪。

### 模型网关

- 普通用户选择供应商、模型和密钥后测试连接；自定义URL与协议放高级设置。
- 适配器统一管理请求/回答、流式、超时取消、错误、用量和能力声明，不假定每个模型都支持JSON、图像、工具调用或推理参数。
- 本地明确动作零API；需要检索时先取证；复杂分析再按能力与预算请求模型。安全或高风险问题不能仅凭字数分档。
- 搜索工具独立启用，展示实际网页来源；默认不把整份私人记忆发送给搜索服务。
- “网页会员/订阅登录”与“可供应用调用的模型API授权”不能混用；确切供应商与接口名称需确认。

## 快速交付顺序与验收门槛

### 第一阶段：发布可复现的核心闭环

- 修复简单动作本地优先、电脑只读问答吞动作、课程调动占用失真和会议漏算。
- 一个日程占用引擎同时服务自动安排与秘书冲突查询：固定课程/会议为硬冲突；有截止但尚未安排的作业是工作量风险，不能一律禁止用户踢球。
- 时间不完整就追问；会议/考试目前没有可靠结束时刻，不得把估计时长说成真实安排。
- 打通一次真实手机配对、真实模型问答、点击原文，以及电脑离线时的明确降级。
- 固定三条演示：导入→引用；安排→冲突→确认；调课→标记→撤销。工程模拟与真机结果分别记录。

### 第二阶段：数据安全与可替换后端

- 先完整备份/恢复原件，再实现手机全量与增量同步。
- 提取现有Milvus实现到向量库接口，完成Chroma一套真实集成测试；后续其他库按相同契约扩展。
- 在隔离测试数据中验证断网重试、重复上传、编辑/删除、重建索引和缺失附件；真实资料迁移前列出原件清单、条数、图片数与哈希。
- 电脑后端公开前单独审计资料目录、缓存、密钥、微信读取模块来源/许可证；当前公开App不等于后端已开源。

### 第三阶段：供应商与导入扩展

- 统一手机/电脑模型网关，分别完成实际选定供应商的协议与连接测试；“有适配代码”和“持真实Key验证过”分列。
- TXT/MD、原件HTML、图片、文字PDF、DOCX逐类声明“可检索文字/保原件/保图文布局”的能力；无法解读hdoc时只保留原件，不虚构迁移成功。
- 增加联网搜索工具、检索效果基准和请求成本统计。
- 飞书从单文档权限验收起步；QQ/钉钉先支持用户合法导出样本，未经验证不宣传账号一键全量抓取。

### 第四阶段：手机打包与商店

- 用最新源重新构建原生包、签名/验签；关联源码提交、包哈希及测试范围。
- 先验收Mate 70 Pro、Pura 70 Ultra，再补窄屏、横屏、折叠/平板、安全区、键盘和字体缩放。
- 记录帧时间、掉帧、内存峰值、首屏/检索/输入延迟；不能用桌面自动化耗时代替手机FPS。
- 华为内测与正式上架是不同发布动作，权限/隐私说明须与实际模型、同步和联网功能一致。

## 求职展示的可信边界

目前适合展示：鸿蒙混合应用、本地规则与模型协同、多会话、确认执行/撤销、本地检索与来源、独立电脑RAG工程、公开自动化测试。

目前不应写为已完成：全平台同步、全部模型/向量数据库适配、hdoc全量无损迁移、微信全部历史与媒体自动采集、所有鸿蒙7机型实测丝滑。

更有价值的交付材料是可复现演示、清楚的架构边界、真实问题与修复记录、检索与性能评测，以及本人能讲清楚的设计取舍；不是支持品牌数量。

用户确认本轮面向 AI/Agent 工程师方向，因此优先补齐：

1. 可复现的手机/电脑一体演示与匿名测试资料，克隆说明能走完实际RAG调用链。
2. 路由决策、来源ID、工具确认、错误与撤销回执的可观测记录；日志默认不记密钥或私人正文。
3. 小型人工标注检索集：精确标题、语义改写、日期/状态、无答案、旧版本/删除、来源中的恶意指令；记录Recall@K/MRR及无答案误答率。
4. 统一模型/向量接口及两种后端真实集成测试，而非只有配置下拉框和mock。
5. 记录首字/总延迟、P50/P95、请求数与token用量；流式只更新界面，不在每个token持久化全库。
6. 能解释为何简单动作走规则、为何RAG不能独自判断时间冲突、为何向量库不是唯一数据库，以及断网/删除/重试时如何保全用户资料。
