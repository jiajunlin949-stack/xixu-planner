# 综合优化实现说明 · 2026-10-29—30

本轮按同一条数据流整理，而非把每个点子做成互不关联的演示：

**手动选择并确认资料 → 提取事项线索与时间说法 → 手机规则/检索 → 可选电脑 RRF + 精排 → 逐段核对数据去向 → 模型建议工具 → 参数校验和日程变更对照 → 确认写入/追溯 → 时间信箱与回信对账。**

> 后续已补充导入/容量/通知/隐私/检索/联网优化，详见 [LIMITS_UPGRADE.md](LIMITS_UPGRADE.md)，同样没有运行验收。

## 当前交付的性质

这是**新增开发源码**。用户明确要求不运行、不测试，因此本轮没有启动 App、模型、服务器、Docker 或评测，没有编译原生代码、签名、打包或上传华为；没有新通过率、检索成绩、性能指标或真机兼容结论。旧稳定标签/绿色 CI 不覆盖本轮代码。不能据此声称安装到手机即可无缺陷使用。

## 时间信箱的产品取舍

它是独立入口，默认关闭，用户选择重要事项并可分别静音。前夜来信采用**明确标注的未来视角推演**，只引用记录中的事项、截止时间、标记状态、进度变更和主动同意复用的原话；不编造宿舍、室友、熬夜、真实完成时间或睡眠。只给一个开始动作，不生成日程表。

进入七天/阶段/前夜最多三个时点；每周总共最多两封，不补发已经错过的所有阶段。信封无强制弹窗，拆开后可封存一句回信；回信不自动建任务。到期后并排保留来信、回信与用户亲自填写的对账。原话引用保留来源事项与时间，用户不勾选就不复用。语气是温柔/实话/直接，默认实话；直接也不生成羞辱或心理诊断。

正文和独立原件一样重要：信件、回信、对账、同意复用的原话都进入完整手机快照。卡片使用现有主题色、轻量透明层与 transform/opacity，减少动态模糊；支持减少动态效果偏好，没有增加全屏持续动画。

## 还需要单独完成的验证/深度能力

- 本轮全部新路径仍需后续运行与人工验收，尤其 ArkTS 编译、文件选择/恢复、网络断开与取消、模型协议真实响应、两段审批、同一数据在并发编辑时的行为。
- 时序推理尚不自动断定跨来源通知的权威性；地点、范围规则的覆盖及批次消歧需进一步扩展。当前电话/编号规则并非通用隐私识别系统。
- 轻量精排是明确可解释的词项/标题/短语加权，默认仍可用词项精排，另有可选本地 CrossEncoder（未运行）；未测真实语料 Recall/MRR、未测手机语义 Embedding。
- 目前只做手动导入和用户主动同步；不恢复自动账号采集/目录监听。hdoc 可靠解码、真实74条迁移、聊天导出样本全覆盖、真机矩阵仍没有因此完成。
- 原生安全存储的单条1024字节限制已在源码中改为加密分块+清单发布，旧 Key/配对内容只在新记录完整写好后替换；仍需真机验证，不能称为实际故障已复现并解决。
