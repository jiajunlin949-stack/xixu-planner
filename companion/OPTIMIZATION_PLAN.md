# 综合优化实施计划

范围：同时落实用户给出的五项基础优化、工具与可观测/评测建议，以及承诺发现、时序资料、数据离机确认、计划变更对照、级联路由和时间信箱。用户明确要求只写代码，不运行应用、构建或评测；本计划与实现进度不能充当运行结果。

统一数据流：手动导入 → 带出处的承诺/变更候选 → 本机工具与检索 → 必要时升级电脑检索/模型 → 数据发送前确认 → 操作差异预览与确认 → 版本日志/时间信箱 → 完整备份。

## 实施分层

1. **共享领域层**：JSON Schema工具契约；本机Tool Registry；按会话保存的日期/时间/目标补全；只读日程查询与硬冲突/DDL压力分开；写入前校验与确认；日程差异和可回退日志。
2. **资料理解层**：只分析用户已确认导入或保存的资料；规则抽取承诺，按原消息时间解释相对日期；去重、保留建议出处，不自动新建日程。时序关系须匹配对象、课程和范围，未知时间不补造，不能简单让最新一条覆盖所有旧消息。
3. **模型与隐私层**：手机/电脑共用供应商配置契约与能力开关；统一流式事件、取消、超时；问题、历史和资料一起做出境预览与脱敏。用户删去的片段不能偷偷补回请求；姓名脱敏不是“正则保证识别全部姓名”。
4. **检索层**：本机词汇/别名与语义改写覆盖、严格结构化筛选；电脑RRF候选Top20，再以轻量可解释重排取Top5；来源版本与时序信息保留。检索分数不冒充校准概率，模型异常可回退到文字结果。
5. **完整资料层**：手机完整ZIP包含业务快照、图片、导入原件、真实来源时间与新功能状态，排除密钥/配对凭据；分块导出/读取，校验全套清单后才提交恢复，不覆盖未完整验证的现有资料。
6. **时间信箱**：独立入口、低干扰未读提示、三种口吻；重要事项须用户选择，默认每周最多2封、每事项最多3封。信件采用条件式未来叙述，素材只来自真实事项、进度日志和用户主动留存的原话。回复封存、到期对照、留给下一次的话均不自动变更日程；没有记录的睡眠/地点/实际完成时间不推断。
7. **可观测与评测**：本地记录路由、来源编号、耗时、确认状态、取消/错误及工具名称，默认不记录问题/正文/密钥；提供脱敏导出和明确空状态。准备50条路由样本、30问检索样本及指标定义/离线脚本，结果未运行就标“未运行”，不写虚构准确率、Recall@5、MRR或截图。

## 约束

- 不恢复账号自动读取、后台目录监听或全量历史采集。
- 不把工具注册表叫作已经接通MCP；MCP协议接入与本项目Schema工具注册是不同交付层级。
- 不自动发送私人资料给模型；不以脱敏代替用户确认。
- 不自动接受承诺、调课或时间信箱的建议；不让相似度或较晚的发送时间成为唯一事实裁决。
- 不用未来角色包装虚构事实，不羞辱或诊断用户，不依据深夜操作时间断言用户熬夜。
- 所有新增状态纳入备份及容量约束；原有用户资料、独立私人知识库和签名文件保留。
